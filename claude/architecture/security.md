# Security hardening

Three-layer defense (middleware + server authz + RLS), rate limits, content-security headers, file-upload validation, secret isolation, audit trail. None of these are optional.

## 1. Three layers of authorization (never trust one alone)

1. **Edge middleware** (`web/src/middleware.ts`) — redirects requests to `/admin/*` without a session cookie to `/login`. Cheap filter; not authz.
2. **Server-side authz** — first line of every server action: `await requireRole('admin')` (helper in `web/src/lib/auth/require.ts`). Reads cookie, fetches profile, checks role. Throws on failure. **This is the real gate.**
3. **Postgres RLS** — even if (2) is bypassed, RLS blocks anon/viewer writes. Last line of defense.

## 2. RLS policies

All catalog tables have RLS enabled. Public select policies on child tables use `EXISTS` subqueries against the parent product so unpublished/deleted parents can't leak their children.

```sql
-- Parent: products
CREATE POLICY products_public_select ON products FOR SELECT
  USING (deleted_at IS NULL AND is_published = true);

-- Children: each one joins back to parent
CREATE POLICY images_public_select ON product_images FOR SELECT
  USING (
    deleted_at IS NULL
    AND license_status IN ('owned', 'licensed', 'public_domain')
    AND EXISTS (
      SELECT 1 FROM products p
      WHERE p.id = product_images.product_id
        AND p.is_published = true
        AND p.deleted_at IS NULL
    )
  );

CREATE POLICY variants_public_select ON product_variants FOR SELECT
  USING (
    deleted_at IS NULL
    AND EXISTS (
      SELECT 1 FROM products p
      WHERE p.id = product_variants.product_id
        AND p.is_published = true
        AND p.deleted_at IS NULL
    )
  );

CREATE POLICY attrs_public_select ON product_attributes FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM products p
      WHERE p.id = product_attributes.product_id
        AND p.is_published = true
        AND p.deleted_at IS NULL
    )
  );

-- product_tags, product_option_values, variant_option_values follow the same shape.
```

**Admin writes** — any authenticated profile with `role IN ('owner','admin','editor')` can SELECT/INSERT/UPDATE/DELETE on every catalog table including unpublished and soft-deleted rows.

**Ops tables** (`audit_logs`, `background_jobs`, `import_runs`, `ai_generations`, `search_logs`, `search_synonyms`) — admin-only select; all inserts via service-role from server actions, no client policy permits insert.

**RLS attack test** runs in CI (P1-T06, again at P5-T08): script with an anon Supabase client tries to read (a) image of a soft-deleted product, (b) variant of an unpublished product, (c) attribute of a soft-deleted product. All must return 0 rows. Deploy blocked if any leaks.

## 3. Rate limits

Implemented via Upstash Redis (or Vercel KV) keyed on IP for anon, user id for authenticated.

| Route | Anon limit | Authenticated limit | Window |
|---|---|---|---|
| `/api/auth/*` (login, reset) | 10 | — | 5 min |
| `/api/search` (when added; SSR pages don't hit it) | 30 | — | 1 min |
| `/api/admin/images/upload` | — | 30 | 1 min |
| `/api/admin/products/*` (mutations) | — | 120 | 1 min |
| All other admin mutations | — | 120 | 1 min |

Excess returns 429 with a `Retry-After` header.

## 4. CSRF

Server Actions use Next.js's built-in same-origin check (default in App Router). Route Handlers that mutate require a `x-csrf-token` header bound to the session — generated by the server on page load, stored in a httpOnly cookie pair, verified by middleware.

## 5. File-upload validation

Multipart uploads to `/api/admin/images/upload`:
- MIME sniff via `file-type` package (don't trust client-supplied `Content-Type`).
- Allowed: `image/webp`, `image/jpeg`, `image/png`, `image/heic`, `image/heif`.
- Max size: 5 MB.
- Max dimensions: 4000 × 4000 px.
- EXIF stripped via sharp.
- Reject silently? No — return 400 with a clear message so the admin can correct.

## 6. Service-role key isolation

- The only file allowed to import `SUPABASE_SERVICE_ROLE_KEY` is `web/src/lib/db/admin.ts`.
- That file is only allowed to be imported by files under `web/src/app/admin/**` and `web/src/app/api/admin/**` and `scripts/**`.
- An ESLint rule (`no-restricted-imports`) enforces this. Adding `// eslint-disable` to bypass it requires a code review.
- Vercel function configuration: server-only env vars not exposed to the browser bundle (Next.js default for non-`NEXT_PUBLIC_` vars).

## 7. Session policy

- 24h activity lifetime; hard expire at 7 days.
- 4h idle timeout on `/admin/*` (client-side check; refresh extends).
- Sign-out invalidates the refresh token globally (`scope: 'global'`).
- TOTP 2FA required for `owner` accounts on `/admin/*` (Supabase AAL2).

## 8. Security headers (next.config.ts)

```ts
const csp = [
  "default-src 'self'",
  "script-src 'self' 'unsafe-inline' 'unsafe-eval' https://va.vercel-scripts.com",
  "style-src 'self' 'unsafe-inline'",
  "img-src 'self' data: blob: https://*.supabase.co https://djl2kq23xfhqi.cloudfront.net",
  "font-src 'self' data:",
  "connect-src 'self' https://*.supabase.co https://*.ingest.sentry.io https://va.vercel-scripts.com",
  "frame-ancestors 'none'",
  "base-uri 'self'",
  "form-action 'self'",
].join('; ');

headers: [
  { key: 'Content-Security-Policy', value: csp },
  { key: 'Strict-Transport-Security', value: 'max-age=31536000; includeSubDomains; preload' },
  { key: 'X-Content-Type-Options', value: 'nosniff' },
  { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
  { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
  // X-Frame-Options is redundant with CSP frame-ancestors but kept for older browsers
  { key: 'X-Frame-Options', value: 'DENY' },
]
```

Note: `unsafe-inline` and `unsafe-eval` in `script-src` are required by Next.js's runtime + Vercel Analytics. Acceptable tradeoff; revisit if we move to strict CSP with nonces (more work, marginal gain at MVP scale).

## 9. Markdown sanitization

Product descriptions are markdown. Rendered via `react-markdown` + `rehype-sanitize` (no raw HTML allowed). The sanitize schema strips `<script>`, `<iframe>`, event handlers, `javascript:` URLs.

## 10. Secret management

- `.env.local` is gitignored; pre-commit hook (Husky) blocks any file matching `*.env*`.
- Production env vars set in Vercel dashboard, pulled locally via `vercel env pull` when needed.
- Rotating the Supabase service-role key: see [runbook: rotate-secrets](../runbooks/rotate-secrets.md).
- Dependabot weekly; `pnpm audit` in CI.
- Pin to exact versions for `@supabase/*`, `next`, `react`.

## 11. Soft delete + audit

- Soft delete is the default. Hard delete requires a typed-confirmation dialog and writes an `audit_logs` row.
- Bulk delete is always soft.
- Every mutation writes to `audit_logs` with before/after.

## 12. What we don't do (out of MVP)

- WAF in front of Vercel — not needed at our scale.
- Penetration testing — owner can commission a one-time pass post-launch.
- SOC 2 / ISO certification — not relevant for a single-shop e-commerce site.
